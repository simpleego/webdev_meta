# 보안강화, UI/UX
> 앞서 구현한 핵심 기능에 **보안, UI/UX, 예외 처리**를 추가하여 실제 서비스 수준으로 프로젝트의
> 완성도를 높이는 방법을 구체적인 코드와 함께 단계별로 제시

### \#\# 🔐 1. 보안 강화 (Security Hardening)

현재 시스템은 학번만 알면 누구나 출석 요청을 보낼 수 있어 매우 취약합니다. **JWT(JSON Web Token) 기반의 인증 시스템**을 도입하여 허가된 사용자만 API를 호출할 수 있도록 강화하겠습니다.

**개선 흐름:**

1.  **로그인**: 학생이 학번과 비밀번호로 로그인하면, 서버는 유효성을 검증하고 **Access Token**을 발급합니다.
2.  **API 요청**: 학생은 이후 모든 API 요청 시 발급받은 Token을 **HTTP 헤더**에 담아 보냅니다.
3.  **서버 검증**: 서버는 요청 헤더의 Token을 검증하여 유효한 사용자인지 확인하고 요청을 처리합니다.

-----

#### **Backend (Spring Security & JWT 라이브러리 추가)**

**1. 의존성 추가 (`build.gradle`)**

```groovy
// Spring Security
implementation 'org.springframework.boot:spring-boot-starter-security'
// JWT 라이브러리 (jjwt)
implementation 'io.jsonwebtoken:jjwt-api:0.11.5'
runtimeOnly 'io.jsonwebtoken:jjwt-impl:0.11.5'
runtimeOnly 'io.jsonwebtoken:jjwt-jackson:0.11.5'
```

**2. JWT 생성 및 검증 로직 구현 (`JwtTokenProvider.java`)**

  * 토큰 생성, 유효성 검증, 정보 추출을 담당하는 클래스를 만듭니다.

<!-- end list -->

```java
@Component
public class JwtTokenProvider {
    // 비밀키, 토큰 유효시간 등 설정
    private final Key key = Keys.secretKeyFor(SignatureAlgorithm.HS256);
    private final long accessTokenValidityInMilliseconds = 3600000; // 1시간

    public String createToken(String studentNumber) {
        Date now = new Date();
        Date validity = new Date(now.getTime() + accessTokenValidityInMilliseconds);

        return Jwts.builder()
                .setSubject(studentNumber)
                .setIssuedAt(now)
                .setExpiration(validity)
                .signWith(key)
                .compact();
    }
    
    // ... 토큰 검증 및 정보 추출 메소드 추가
}
```

**3. Spring Security 설정 (`SecurityConfig.java`)**

  * 특정 URL(로그인, 회원가입 등)은 허용하고, 나머지 요청은 인증을 거치도록 설정합니다.

<!-- end list -->

```java
@Configuration
@EnableWebSecurity
@RequiredArgsConstructor
public class SecurityConfig {
    
    private final JwtTokenProvider jwtTokenProvider;

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .httpBasic().disable()
            .csrf().disable() // REST API이므로 CSRF 비활성화
            .sessionManagement().sessionCreationPolicy(SessionCreationPolicy.STATELESS) // 세션 사용 안함
            .and()
            .authorizeRequests()
            .antMatchers("/api/login", "/register").permitAll() // 로그인은 모두 허용
            .anyRequest().authenticated() // 나머지는 인증 필요
            .and()
            // JWT 필터를 UsernamePasswordAuthenticationFilter 전에 추가
            .addFilterBefore(new JwtAuthenticationFilter(jwtTokenProvider), UsernamePasswordAuthenticationFilter.class);
        
        return http.build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return PasswordEncoderFactories.createDelegatingPasswordEncoder();
    }
}
```

  * `JwtAuthenticationFilter`: 요청 헤더에서 JWT를 파싱하여 인증 정보를 SecurityContext에 저장하는 커스텀 필터입니다.

**4. 로그인 API 수정**

  * 로그인 성공 시 JWT를 생성하여 응답 본문에 담아 반환하도록 수정합니다.

#### **Frontend (JavaScript)**

**1. 로그인 및 토큰 저장**

  * 로그인 성공 후 서버로부터 받은 JWT를 브라우저의 `localStorage`에 저장합니다.

<!-- end list -->

```javascript
// login.js
async function login() {
    // ... id, password 가져오기
    const response = await fetch('/api/login', { /* ... */ });
    
    if (response.ok) {
        const { accessToken } = await response.json();
        localStorage.setItem('accessToken', accessToken); // 토큰 저장
        window.location.href = '/attendance.html'; // 출석 페이지로 이동
    } else {
        // 로그인 실패 처리
    }
}
```

**2. API 요청 시 헤더에 토큰 추가**

  * `face-api.js`를 사용하는 `fetch` 요청의 헤더에 저장된 JWT를 담아 보냅니다.

<!-- end list -->

```javascript
// attendance.js
async function checkIn(studentNumber) {
    const accessToken = localStorage.getItem('accessToken');
    if (!accessToken) {
        alert('인증 정보가 없습니다. 다시 로그인해주세요.');
        window.location.href = '/login.html';
        return;
    }

    const response = await fetch('/api/attendance/check', {
        method: 'POST',
        headers: {
            'Content-Type': 'application/json',
            'Authorization': `Bearer ${accessToken}` // Authorization 헤더에 토큰 추가
        },
        body: JSON.stringify({ studentNumber: studentNumber })
    });
    // ...
}
```

### \#\# ✨ 2. UI/UX 개선 (User Interface/Experience Enhancement)

#### **2. 얼굴 데이터 관리 기능**

  * 학생이 로그인 후 **자신이 등록한 얼굴 사진/데이터를 확인하고 삭제**할 수 있는 '마이페이지'를 제공하여 사용자 통제권을 높입니다. 이 기능은 개인정보보호 측면에서도 중요합니다.

#### **3. 예외 상황 대처 방안**

  * **(1) 수동 출석 버튼**: 카메라가 없거나 얼굴 인식이 계속 실패하는 사용자를 위해, 비밀번호 재확인 등 추가 인증을 거쳐 **수동으로 출석**할 수 있는 버튼을 제공합니다.
  * **(2) 재시도 버튼**: "인식에 실패했습니다" 메시지와 함께 "다시 시도" 버튼을 제공하여 사용자가 능동적으로 재시도할 수 있게 합니다.

### \#\# 🛠️ 3. 예외 처리 (Robust Exception Handling)

예상치 못한 에러가 발생했을 때 시스템이 비정상적으로 종료되는 것을 막고, 사용자에게 친절한 안내 메시지를 보여주도록 서버와 클라이언트 양쪽의 예외 처리 로직을 강화합니다.

-----

#### **Backend (Global Exception Handler)**

  * `@RestControllerAdvice`를 사용하여 모든 Controller에서 발생하는 예외를 한 곳에서 중앙 관리합니다.

**1. 표준 에러 응답 DTO 생성 (`ErrorResponse.java`)**

```java
@Getter
@RequiredArgsConstructor
public class ErrorResponse {
    private final String errorCode;
    private final String message;
}
```

**2. 전역 예외 처리기 구현 (`GlobalExceptionHandler.java`)**

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 직접 정의한 예외 처리 (e.g., 학생을 찾지 못함)
    @ExceptionHandler(StudentNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleStudentNotFoundException(StudentNotFoundException ex) {
        ErrorResponse response = new ErrorResponse("STUDENT_NOT_FOUND", ex.getMessage());
        return new ResponseEntity<>(response, HttpStatus.NOT_FOUND);
    }

    // 이미 출석한 경우
    @ExceptionHandler(AlreadyCheckedInException.class)
    public ResponseEntity<ErrorResponse> handleAlreadyCheckedInException(AlreadyCheckedInException ex) {
        ErrorResponse response = new ErrorResponse("ALREADY_CHECKED_IN", ex.getMessage());
        return new ResponseEntity<>(response, HttpStatus.CONFLICT); // 409 Conflict
    }

    // JWT 관련 예외 처리
    @ExceptionHandler(JwtException.class)
    public ResponseEntity<ErrorResponse> handleJwtException(JwtException ex) {
        ErrorResponse response = new ErrorResponse("INVALID_TOKEN", "유효하지 않은 토큰입니다.");
        return new ResponseEntity<>(response, HttpStatus.UNAUTHORIZED); // 401 Unauthorized
    }

    // 그 외 모든 예외 처리
    @ExceptionHandler(Exception.class)
    public ResponseEntity<ErrorResponse> handleException(Exception ex) {
        ErrorResponse response = new ErrorResponse("INTERNAL_SERVER_ERROR", "서버 내부 오류가 발생했습니다.");
        // 서버 로그에는 실제 에러를 기록해야 합니다. log.error("...", ex);
        return new ResponseEntity<>(response, HttpStatus.INTERNAL_SERVER_ERROR);
    }
}
```

  * `StudentNotFoundException`, `AlreadyCheckedInException` 등은 직접 정의한 Custom Exception입니다. `Service` 로직에서 `throw new StudentNotFoundException("해당 학번의 학생을 찾을 수 없습니다.");` 와 같이 사용합니다.

-----

#### **Frontend (JavaScript)**

  * `fetch` API 호출 시 `.catch()`를 사용하거나 `try...catch` 구문을 활용하여 네트워크 에러 및 서버의 에러 응답을 처리합니다.

<!-- end list -->

```javascript
// attendance.js
async function checkIn(studentNumber) {
    // ... 토큰 가져오기 ...
    try {
        const response = await fetch('/api/attendance/check', { /* ... */ });

        if (!response.ok) {
            // 서버가 4xx, 5xx 상태 코드를 반환한 경우
            const errorData = await response.json(); // 백엔드의 ErrorResponse DTO를 받음
            throw new Error(errorData.message);
        }

        const resultMessage = await response.text();
        messageDiv.innerText = resultMessage;

    } catch (error) {
        console.error("출석 처리 실패:", error);
        // 사용자에게 친절한 에러 메시지 표시
        messageDiv.innerText = `오류: ${error.message || '네트워크 연결을 확인해주세요.'}`;
        
        // 이전에 성공 처리 목록에 추가했다면, 실패했으므로 다시 제거
        checkedInStudents.delete(studentNumber);
    }
}
```

이러한 개선 사항들을 적용하면, 프로젝트는 단순한 기능 구현을 넘어 **안정적이고(Secure), 사용자 친화적이며(User-friendly), 견고한(Robust)** 서비스로 거듭날 수 있습니다.
