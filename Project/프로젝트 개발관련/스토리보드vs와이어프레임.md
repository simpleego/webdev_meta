# 스토리보드vs와이어프레임
> 와이어프레임(Wireframe)과 스토리보드(Storyboard)는 둘 다 기획 단계에서 사용되지만, 목적과 초점이 명확히 다릅니다.

간단히 말해, \*\*와이어프레임은 '화면의 구조(뼈대)'\*\*를 보여주고, \*\*스토리보드는 '사용자의 경험 흐름(시나리오)'\*\*을 보여줍니다.

## 와이어프레임 vs. 스토리보드 비교

| 구분 | ✏️ 와이어프레임 (Wireframe) | 🎬 스토리보드 (Storyboard) |
| :--- | :--- | :--- |
| **목적** | 페이지의 **구조 설계** 및 **요소 배치** 정의 | 사용자의 **작업 흐름(Task Flow)** 및 **경험 시각화** |
| **초점** | **UI (사용자 인터페이스)**\<br\>정보의 계층 구조, 기능의 배치 | **UX (사용자 경험)**\<br\>사용자의 행동, 화면의 순서, 인터랙션 |
| **형태** | **정적인(Static) 단일 화면**\<br\>단순한 선, 도형, 텍스트로 구성 (Low-Fidelity) | **연속적인(Sequential) 여러 화면**\<br\>여러 와이어프레임과 설명(Annotation)으로 구성 |
| **범위** | 주로 **개별 페이지** 또는 템플릿 단위 | 사용자가 특정 목표를 달성하는 **전체 과정** |
| **핵심 질문** | "이 페이지에 **무엇이 어디에** 들어가는가?" | "**어떻게** 사용자가 이 목표를 달성하는가?" |
| **비유** | **건축 설계도** | **영화 콘티** 또는 **만화책** |

-----

### 언제, 어떻게 사용하나요?

두 가지는 별개가 아니라 상호 보완적으로 사용됩니다.

1.  **와이어프레임 먼저\!**: 먼저 개별 화면에 어떤 버튼, 이미지, 텍스트가 들어갈지 와이어프레임으로 \*\*'뼈대'\*\*를 잡습니다. 예를 들어 '로그인 페이지', '메인 페이지', '상품 상세 페이지'의 와이어프레임을 각각 만듭니다.

2.  **스토리보드로 연결\!**: 그 다음, 만들어진 와이어프레임들을 가져와 사용자의 행동 순서에 따라 연결하여 \*\*'이야기'\*\*를 만듭니다.

      * **예시**: "사용자가 \*\*'메인 페이지(와이어프레임 1)'\*\*에서 \*\*'로그인 버튼'\*\*을 누르면, \*\*'로그인 페이지(와이어프레임 2)'\*\*가 나타난다. 여기서 아이디와 비밀번호를 입력하고 \*\*'로그인 버튼'\*\*을 누르면 다시 \*\*'메인 페이지(와이어프레임 1)'\*\*로 돌아오며 '로그인' 버튼이 '내 정보'로 바뀐다." 와 같이 흐름을 설명하는 것이 스토리보드입니다.

-----

### 한눈에 보는 핵심 정리

  * **와이어프레임 (Wireframe)** ✏️: '뼈대', '설계도'. **정적인 화면 구조**에 집중합니다.
  * **스토리보드 (Storyboard)** 🎬: '시나리오', '흐름'. 사용자의 **동적인 경험과 과정**에 집중합니다.
